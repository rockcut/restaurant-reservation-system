# 飲食店向け予約管理システム

個人経営の飲食店 **AuVingtQuatre** で実際に使用することを目的として開発している、予約管理Webアプリケーションです。

電話で受けた予約を紙で管理していた店舗業務をiPad上で管理できるようにし、予約状況や席の利用状況を分かりやすく可視化することを目的としています。

現在は店舗のiPadに導入し、実際の運用を想定した試験・改善を進めています。

## 開発背景

店舗では、電話で受けた予約を紙を中心に管理していました。

この方法では、

- 予約状況を確認するために紙を確認する必要がある
- どの席にどの予約が入っているか把握しにくい
- 複数テーブルを連結して使用する予約がある
- 予約時に想定した席と実際に案内した席が異なる場合がある
- スタッフによって必要な操作権限が異なる

といった課題があります。

そこで、実際に勤務している店舗を対象として、現場スタッフの意見を取り入れながら予約管理システムを開発しています。

単に紙の予約表をデジタル化するのではなく、店舗特有の席配置や実際のオペレーションに対応することを重視しています。

## 主な機能

### 予約管理

- 予約の登録
- 予約内容の編集
- 予約の削除
- 日付ごとの予約表示
- 席ごとの予約状況の可視化
- 複数席を使用する予約への対応

### 予約検索

予約者名または電話番号から予約を検索できます。

予約者名については、入力時の表記ゆれを考慮し、

- `たなか`
- `タナカ`

のようなひらがな・カタカナの違いを吸収して検索できるようにしています。

保存されている予約者名そのものは変更せず、検索時のみ文字列を正規化しています。

### 席の連結

店舗の実際の席配置に合わせ、以下のような複数テーブルの連結予約に対応しています。

- テーブル1 + 2
- テーブル2 + 3
- テーブル1 + 2 + 3
- テーブル5 + 6

単一の席番号だけではなく、1件の予約に対して複数の席を紐づけて管理しています。

### 席交換

予約時に設定した席と、当日実際にお客様を案内した席が異なる場合に対応するため、席交換機能を実装しています。

通常の予約編集とは分離した専用の席交換モードを用意し、

- 1席同士の交換
- 2テーブルを使用する予約同士の交換

に対応しています。

### お祝いプレート入力支援

店舗でよく使用するメッセージを定型文として選択できます。

例：

- Happy Birthday
- Bon Mariage
- Happy Wedding
- Happy 10th anniversary

定型文を選択した後に自由に編集することもできます。

### 予約時間選択

予約時間は店舗の営業時間に合わせて、

**17:00〜22:00を10分刻み**

で選択できるようにしています。

### 権限管理

スタッフごとにアカウントを発行し、以下の2種類の権限を設定しています。

#### Editor

- 予約の登録
- 予約の編集
- 予約の削除
- 席交換
- 予約検索・閲覧

#### Viewer

- 予約状況の閲覧
- 予約詳細の確認
- 日付変更
- 予約検索

Viewerには予約の追加・変更・削除・席交換を許可していません。

フロントエンドで編集UIを非表示にするだけでなく、SupabaseのRow Level Security（RLS）によってデータベース側でも更新を制限しています。

### パスワード変更

スタッフは管理者から発行された初期パスワードでログインした後、自分でパスワードを変更できます。

これにより、スタッフが他サービスで使用しているパスワードを管理者へ共有する必要がない運用にしています。

## 席構成

店舗の席構成は以下の通りです。

### テーブル

- 1
- 2
- 3
- 5
- 6

※ テーブル4はありません。

### カウンター

- C1
- C2
- C3

テーブル1・2・3、およびテーブル5・6は必要に応じて連結して利用できます。

この店舗固有の席構成をシステム上でも表現しています。

## 設計上の工夫

### 予約と物理的な席割り当てを分離

当初は予約データに単一の席番号を保持していました。

しかし、開発途中で複数テーブルを使用する予約に対応する必要が生じたため、予約と席の関係を別テーブルで管理する構成へ変更しました。

現在は、

- `reservations`
- `reservation_seats`

を分け、1件の予約に複数の席を紐づけられるようにしています。

これにより、連結席や席交換にも対応できるようになりました。

### 閲覧と予約追加の操作を分離

予約済みの席をクリックした場合は「予約詳細の確認」を優先し、空席をクリックした場合は「新規予約の席選択」として扱います。

同じ席UIを利用しながらも、ユーザーの操作目的によって処理を分けることで、店舗での誤操作を減らすようにしています。

### データベース側でも権限制御

Editor / Viewerの権限制御はフロントエンドだけに依存せず、Supabase RLSでも制御しています。

そのため、Viewerが直接データベースへの更新処理を実行しようとしても、予約データを変更できない構成になっています。

## 環境変数

Supabaseへの接続には環境変数を使用します。

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
```

実際の値を含む `.env.local` などのファイルはGitHubへコミットしません。

## ローカルでの起動

`frontend` ディレクトリへ移動します。

```bash
cd frontend
```

依存パッケージをインストールします。

```bash
npm install
```

開発サーバーを起動します。

```bash
npm run dev
```

起動後、ブラウザからローカル環境へアクセスします。

## 開発フロー

機能追加や修正はGitHub Issuesを利用して管理しています。

基本的に、

```text
Issue作成
   ↓

   ↓

   ↓
Commit / Push
   ↓
Issue Close
   ↓
```

という流れで開発しています。

また、実際に店舗スタッフから得たフィードバックについてもIssue化し、改善内容と実装履歴を残すようにしています。
