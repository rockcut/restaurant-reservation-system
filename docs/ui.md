# UI設計

## 1. 概要

本システムは、飲食店 AuVingtQuatre のスタッフが主に店舗iPadから利用する予約管理システムである。

営業中でも予約状況を素早く確認できることを重視し、以下の方針でUIを設計する。

- 予約状況を席レイアウトから直感的に確認できる
- 予約済みの席を押すと予約詳細を確認できる
- 空席を押すと新規予約を登録できる
- 通常の予約操作と席交換操作を明確に分離する
- iPadのタッチ操作を前提とする
- Editor / Viewerの権限に応じて操作可能なUIのみ表示する

---

# 2. 画面構成

主な画面は以下の4画面とする。

```text
/login
  │
  ▼
/
予約管理画面
  ├── /search
  │     予約検索画面
  │
  └── /change-password
        パスワード変更画面
```

---

# 3. ログイン画面

## URL

```text
/login
```

## 目的

スタッフ本人を認証し、予約管理システムへログインする。

## 表示項目

- システム名
- メールアドレス入力欄
- パスワード入力欄
- ログインボタン
- エラーメッセージ

## 操作

### ログイン成功

Supabase Authenticationによる認証成功後、予約管理画面 `/` へ遷移する。

### ログイン失敗

以下のメッセージを表示する。

```text
メールアドレスまたはパスワードを確認してください
```

---

# 4. 予約管理画面

## URL

```text
/
```

## 目的

指定日の予約状況を席レイアウト上で確認し、予約の登録・確認・編集などを行う。

本システムのメイン画面とする。

---

# 5. ヘッダー

画面上部には、予約管理に必要な操作を配置する。

主な操作：

- 予約検索
- パスワード変更
- ログアウト

Editorの場合は予約編集に必要な機能を利用できる。

Viewerの場合は予約を変更する操作を表示しない。

---

# 6. 日付ナビゲーション

現在表示している予約の日付を変更する。

以下の操作を提供する。

- 前日へ移動
- 翌日へ移動
- 日付を直接指定

日付を変更した場合、以前の日付で選択していた席や編集中の状態を解除する。

対象：

- 選択中の席
- 予約入力フォーム
- 編集中の予約
- 席交換状態

これにより、別の日付へ移動した際に以前の選択状態が残らないようにする。

---

# 7. 席レイアウト

店舗の実際の席配置をもとに、予約状況を表示する。

## テーブル席

```text
1
2
3
5
6
```

テーブル4は存在しない。

## カウンター席

```text
C1
C2
C3
```

内部的には以下のIDを使用する。

```text
C1 = 101
C2 = 102
C3 = 103
```

---

# 8. 予約済み席の表示

予約が存在する席については、空席と視覚的に区別して表示する。

複数席を利用する予約の場合、その予約が使用している席を連結された予約として表示する。

対象となる連結席：

```text
1 + 2
2 + 3
1 + 2 + 3
5 + 6
```

---

# 9. 通常モードでの席クリック

通常モードでは、

**予約済みの席**

と

**空席**

でクリック時の動作を分ける。

---

## 9.1 予約済み席

予約済みの席をクリックした場合は、

**予約詳細の確認**

を最優先する。

クリックした席に紐づく予約を検索し、その予約が使用しているすべての席を選択状態とする。

例：

```text
予約A
席：2 + 3
```

の場合、2または3をクリックすると、

```text
selectedSeats = [2, 3]
```

となり、予約Aの詳細を表示する。

以前別の席を選択していた場合でも、その選択状態を引き継がない。

### 設計理由

予約済み席をクリックするスタッフの主な目的は、

```text
その席の予約内容を確認すること
```

であるため。

---

## 9.2 空席

空席をクリックした場合は、

**新規予約の席選択**

として扱う。

複数の空席を選択することで、連結席予約を作成できる。

許可される席構成：

```text
[1]
[2]
[3]
[5]
[6]

[1, 2]
[2, 3]
[1, 2, 3]
[5, 6]

[101]
[102]
[103]
```

許可されていない席構成は予約できない。

---

# 10. 予約詳細

予約済みの席を選択すると、その予約の詳細を表示する。

表示する情報：

- 予約者名
- 人数
- 予約時間
- 使用席
- コース
- アレルギー
- お祝いプレート
- プレートメッセージ
- 電話番号
- 備考

Viewerもすべての予約詳細を閲覧できる。

---

# 11. 予約登録フォーム

空席を選択すると、新規予約登録フォームを表示する。

Editorのみ利用可能とする。

## 入力項目

- 予約者名
- 人数
- 予約時間
- コース
- アレルギー
- お祝いプレート
- プレートメッセージ
- 電話番号
- 備考

---

# 12. 予約時間

予約時間は自由入力ではなく選択式とする。

選択可能時間：

```text
17:00
17:10
17:20
...
21:40
21:50
22:00
```

17:00〜22:00まで10分刻みとする。

iPad / iPhoneではブラウザのネイティブ `<select>` UIを利用する。

---

# 13. お祝いプレート

お祝いプレートを希望する場合のみ、プレートメッセージ入力UIを表示する。

定型文：

```text
Happy Birthday
Bon Mariage
Happy Wedding
Happy ●●th anniversary
```

定型文を選択した後でも自由に文章を編集できる。

Anniversaryについては周年数を指定してメッセージを生成する。

---

# 14. 予約編集

予約詳細から既存予約を編集できる。

Editorのみ利用可能。

編集時は既存予約情報をフォームへ設定し、変更後の内容を保存する。

Viewerには編集操作を表示しない。

---

# 15. 予約削除

Editorは予約詳細から予約を削除できる。

誤操作を防ぐため、Viewerには削除操作を表示しない。

---

# 16. 席交換モード

実際の着席位置と予約上の席が異なる場合に使用する。

通常の予約追加・詳細確認とは分離した専用モードとする。

Editorのみ利用可能。

---

## 16.1 1席交換

交換元の席と交換先の席を選択する。

選択完了後、確認操作を行って席を交換する。

---

## 16.2 2席ブロック交換

以下のブロックを交換対象とする。

```text
[1, 2]
[2, 3]
[5, 6]
```

交換元と交換先を選択し、確認後に交換する。

重複する席を含むブロック同士は交換できない。

---

## 16.3 席交換中のUI

席交換モード中は通常の予約追加操作と区別できる表示にする。

これにより、

```text
予約を追加しているのか
席を交換しているのか
```

をスタッフが判断できるようにする。

---

# 17. 予約検索画面

## URL

```text
/search
```

## 目的

予約者名または電話番号から予約を検索する。

## 入力

検索欄を1つ設ける。

入力された文字列を、

- 予約者名
- 電話番号

の両方と比較する。

---

# 18. ひらがな・カタカナ検索

予約者名については、ひらがな・カタカナの表記ゆれを吸収する。

例：

```text
検索：たなか
保存：タナカ

→ 検索結果に表示
```

```text
検索：タナカ
保存：たなか

→ 検索結果に表示
```

DBに保存されている予約者名は変更せず、検索処理の中だけで正規化する。

---

# 19. 検索結果

検索条件に一致する予約を一覧表示する。

複数の予約が一致する場合は複数件表示する。

検索結果は予約日の新しいものを優先して表示する。

検索結果を選択すると、その予約の詳細を表示する。

---

# 20. パスワード変更画面

## URL

```text
/change-password
```

## 目的

ログインしているスタッフ本人が、自分のログインパスワードを変更する。

Editor / Viewerの両方が利用できる。

## 入力項目

- 新しいパスワード
- 新しいパスワード（確認）

## バリデーション

以下を確認する。

- 両方入力されている
- 2つのパスワードが一致している
- パスワードが6文字以上である

## 成功時

```text
パスワードを変更しました
```

を表示する。

## 失敗時

エラーメッセージを表示する。

## その他

「予約管理に戻る」ボタンから `/` へ戻ることができる。

---

# 21. Editor / ViewerによるUIの違い

## Editor

表示する操作：

```text
予約閲覧
予約検索
予約追加
予約編集
予約削除
席交換
パスワード変更
ログアウト
```

## Viewer

表示する操作：

```text
予約閲覧
予約検索
パスワード変更
ログアウト
```

Viewerには以下を表示しない。

```text
予約追加
予約編集
予約削除
席交換
```

---

# 22. エラー時の方針

ユーザー操作によってエラーが発生した場合、可能な限り画面上に分かりやすいメッセージを表示する。

開発者向けの詳細情報については `console.error` 等で確認できるようにする。

---

# 23. レスポンシブ対応

主な利用端末はiPadとする。

ただし以下でも基本操作が可能なレイアウトとする。

- PC
- iPad
- スマートフォン

特にフォームやボタンについては、タッチ操作でも利用しやすいサイズを確保する。

---

# 24. UI設計の基本方針

本システムでは、

**「スタッフが営業中に迷わず操作できること」**

を最優先する。

そのため、

```text
予約済み席
    ↓
予約詳細を見る

空席
    ↓
新しい予約を追加する

席を移動したい
    ↓
席交換モード
```

というように、操作目的ごとに処理を明確に分離する。

機能を追加する場合も、単に操作を増やすのではなく、既存の店舗オペレーションに自然に組み込めるかを基準としてUIを設計する。
